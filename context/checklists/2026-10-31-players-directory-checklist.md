## Global constraints (apply to every task)

- **Wire additions are additive only.** New RPCs, new records, one new `NAME_ERROR_CODES` value. `OpCode`, `Snapshot`, `PlayerInfo`, `RoomInfo`, `FRIEND_LIMITS`, notification codes and existing RPC payloads keep their shape.
- **`@chkobba/protocol` helpers are pure and goja-safe**: ES2017 lib only (no `.at()`, `Object.hasOwn`, `Proxy`, `Math.random`), no `String.prototype.normalize`, no `\p{…}`, no `u`-flag regex. Character work uses explicit `\uXXXX` ranges in the style of `packages/protocol/src/names.ts:58`.
- **Claim keys are ASCII only.** (Task 1.1 probed the opposite of the plan's assumption: Nakama 3.40 enforces no charset on storage keys and the limit is 128 **characters**, not bytes — a 128-char Arabic key succeeds. ASCII-only remains a deliberate design choice: a folded Arabic name can never be a key.) The claim key is `n` + lowercase SHA-256 hex of the folded name; the folded form lives in a value field only.
- Server code bundles to one ES5 goja file: after any server change run `pnpm --filter @chkobba/server build`, restart Nakama and confirm the module loads (validation reference below).
- Hooks `return data` and throw `{ message, code }` with numeric gRPC codes as local consts (`3/5/7/8/9/16`); `nkruntime.Codes` cannot be inlined by Babel. RPCs and hooks are top-level named functions in `apps/server/src/main.ts`.
- Storage permissions: system-owned records (`player_directory` claim + `limits`, `player_stats/*`) are read 0 / write 0; owner-visible records (`player_directory/own/<userId>`, `profile/prefs`) are owner read 1 / write 0.
- Best-effort writes (recent players, competitive stats, backfill, reconciliation) log and never fail a hook, `matchLoop`, `matchLeave` or a sign-in.
- No SQL; Nakama storage, friends, account and RPC APIs only.
- Mobile: no hard-coded UI text (`const tr = useT()`); every string in `en.ts` and `aeb.ts`; names and counts isolated in RTL; skins only through tokens and slots; `marginStart`/`marginEnd`.
- RNTL v14 `render`/`fireEvent` are async — always `await`.
- After adding an expo-router route, run `pnpm --filter @chkobba/mobile start` once to regenerate typed routes before `typecheck`.
- Keep the workspace on Babel 7; if an install re-resolves Babel 8 peers, restore `pnpm-lock.yaml`.
- **Accepted for v1, not to be "fixed" mid-plan**: the friends list renders a Nobody player as offline (no presence arrives). The directory and profile are honest; server-owned presence is future work.
- **`/f/[code]` stays** for legacy shared links even though the code UI retires; the code lookup backend stays too.
- No deployment or hosting.
